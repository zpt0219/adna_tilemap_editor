# autotile_path

2-edge 路网自动图块生成器：**路、河、墙、栅栏、管道**这类线状网络的 16 张图集。

浏览器端，无后端。与 [`autotile_mixer`](../autotile_mixer) 完全独立——不共享代码，
也不共享美术数据。两者解决的是不同的问题：

| | `autotile_mixer` | `autotile_path`（本应用） |
| --- | --- | --- |
| 方案 | blob47（8 邻居，47 张） | 2-edge（4 正交邻居，16 张） |
| 语义 | **区域**：格子是地形，邻居说地形是否延续 | **网络**：格子是路，邻居说路往哪通 |
| 角色 | 三个：地形 A / 描边 / 地形 B | **路面 / 路沿 / 中轴**，其余全透明 |
| 坐标 | 一个：到边界的深度 | **两个：`t` 横跨 + `s` 沿路** |
| 形状 | 烘焙好的距离场 | 运行时解析计算 |
| 图集 | 8×6，192×256 | 4×4，128×128 |

方案本身的推导见 [`../docs/AUTOTILE_SCHEMES.md`](../docs/AUTOTILE_SCHEMES.md)。

## 只有地形 A

blob47 是**地形**方案：图块知道边界两侧分别是什么，所以地形 B 是一种它真的会画的
颜色，还带一圈贴着描边的阴影环。路不是那样。路铺在什么地面上，图块完全不知道，
所以**路沿以外就是没有东西**——alpha 0，不是一个选项，是这个方案的定义。

中轴是第三种颜色，但它属于地形 A —— 它是路面上画的东西，不是第二种地形。

界面里还有一个"地面"取色器，但它只是**试铺画布的底色**，用来判断路配不配这块地。
它不进导出的 PNG，测试里有一条专门守着这件事。

## 两种读法：网络 / 区域

同样 16 张 mask，两种完全不同的美术含义，UI 顶上一个开关，导出的 JSON 里
`scheme` 字段跟着写：

| | **网络**（默认） | **区域** |
| --- | --- | --- |
| 格子是什么 | 一条路 | **就是地形本身** |
| 邻居位说什么 | 路往哪通 | 地形是否延续 |
| 形状 | 到骨架的距离 | 圆角矩形：通的边齐平，不通的边内缩 |
| 中轴 | 有 | **没有**（填充的地形没有骨架） |
| 路面花纹 | 全部 | 单色 / 碎石 / 横向渐变（车辙和横纹要沿路坐标，区域没有） |
| `scheme` | `two-edge-network` | `two-edge-area` |

⚠ **区域读法是"廉价版"，接缝做不到精确，这是方案的账不是实现的。**
`docs/AUTOTILE_SCHEMES.md` §4 算过：一个象限需要 5 种状态，2-edge 只能表达 4 种，
缺的那种是**内凹角**（两条边都通、对角不通），而 4 个 bit 里根本没有对角。
所以 L 形区域的内凹角上有一个台阶。

实测（内缩 2px）：**块状地图 50 条竖接缝里 3 条有断层，占边界像素 0.4%**；
路网形状的地图 7.7%，但那本来就不是区域读法该用的形状。而且
**只要两块图对侧墙的判断一致，接缝就是精确的**——测试断言这一条为 0 例外，
所以偏差全部可归因于那个缺掉的对角，没有别的来源。

⚠ 两个"距离"必须分开，混用会直接破坏平铺：
- `inside` 数所有四条边，决定这个像素在不在区域里；
- `edge` 只数**地形真的停下来的**那些边，四面都通时是 `Infinity`。

路沿画在 `edge` 上、噪点也只动 `edge`。用 `inside` 代替的话，四面都通的格子会被套上
一圈本不该有的描边，而噪点会啃掉必须齐平的边——两个都是这条分开之前的真实 bug。

## 一条路 = 三个阶段

一块图块是三个阶段叠在一个骨架上，每一阶段读上一阶段留下的东西：

| 阶段 | 它决定什么 | 控件 |
| --- | --- | --- |
| **边界** | 轮廓和路沿在哪 | 直线圆角 / 圆弧波浪线 · 距离 · 圆弧半径 · 边界噪点 · 路沿实心度 |
| **中轴** | 中间那条线 | 无 / 直线圆角 / 双直线 / 虚线 / 长短虚线 / 随机长短线 · 宽度 · 周期 |
| **路面** | 中间那块地怎么着色 | 单色 / 横向渐变 / 碎石 / 车辙 / 横纹 |

（这三阶段说的是网络读法；区域读法下中轴整个不存在，路面少两档，见上一节。）

三个互相独立：生成的边界配上随机中轴、或者规整中轴配上抖散的边界，都是可以的组合。

⚠ **图集只有四种颜色**，而且是刻意的。路面纹理需要第二个色调时，用的是调色板里已有
的 `暗色`（路沿的第二个色），不是新造一个——量出来那四个色本身是一条渐变：
`暗色` 正好落在「路面色 → 路沿色」的连线上，走了 53%（RGB 拟合 rms 2.49/255）。
测试守着这条。

### ⚠ 这套常数是拟合一张手绘图得来的，那张图已经不在仓库里了

早期版本回放一张 16px 手绘参考图（`assets/test6.png`），并把它拆成三层来逐层替换。
生成器做到能复现它之后，图和回放路径一起删掉了。**但每一个"实测"的数字都还在**，
因为它们没法从仓库里现存的东西重新推出来：

- 骨架：`bend 11`、`halfWidth 5.25`、`路沿 2`、`dotScale 1.6`，92.70% 像素吻合
- 路沿抖动：最外环 57% 路面色 / 29% 路沿色 / 14% 路沿二色，沿边找不到周期
- 中轴：1 个原图像素宽、贴着轴、段长 1/2/3px，同样无周期；偏移落在 -3/-1/+1
- `手绘` 噪点的格子：4 输出像素，扫出来 rms 0.104（5.3px 是 0.198，8px 是 0.283）

每个数都写在用它的地方，`boundary.ts` 开头有一段专门说这件事。**看到"实测"两个字
不要当成随口取值**——被测的东西只是不在了。

## 形状模型

一格路 = 到**骨架**距离小于阈值的点集。骨架由三部分组成：

- 每个连通方向一条从中心伸到格边的**直臂**；
- 每对垂直臂之间一段**四分之一圆弧**（转角半径 `bend`）；
- 没有邻居时，中心的**一个点**（孤立格画成圆点）。

轮廓不是直接阈值，而是阈值**加位移**：圆弧波浪线沿路加一串真圆弧，边界噪点再加一层
只跟全局位置有关的抖动。路沿是轮廓往里 2px 的一圈，跟着轮廓一起抖。

## 两个坐标：这才是和 blob47 的根本区别

一块地形只有一个有意义的坐标——到边界的深度。**一条路是曲线加了宽度，天然带一套
`(s, t)` 参考系**：

```
t = 到骨架的距离   （横跨路面）
s = 沿骨架的距离   （顺着路走）
```

让人一眼认出"这是路"的东西——中线、车辙、横纹、路沿虚线——**全是 `s` 的函数**。
blob47 一个都表达不了，因为区域没有中轴也没有方向。

### `s` 怎么来，以及它的代价

路网没有全局朝向，所以拿不到弧长；`s` 只能由**无向的世界坐标**拼出来——取"此处
沿路方向的那条世界轴的坐标"。于是：

- **开放边上 `s` 逐像素精确**（实测 16×16 组合、各 bend 下误差 `0.00e+0`），理由和
  `t` 完全一样：靠近格边时最近的骨架元素必是那条垂直于边的直臂。
- 图块用局部坐标画，`s` 和全局的差是 **32 的倍数**，所以**周期整除 32 的花纹跨接缝
  自动同相**。UI 只给 4/8/16/32。

⚠ **代价在拐角，而且比早先写的严重得多。** 转过一半时"沿路轴"从一条世界坐标换到
另一条。这里原本写着差 `0.586 × bend`（bend=4 时 2.3px）——**那个数是错的**：实测
在拟合用的 bend=11 下，两个相邻像素之间差 **14px**，四种拐角全部如此。切换实际发生
在圆弧的切点，不是 45°，所以那句话描述的是一个代码从没实现过的意图。

后果不是"顿挫"是"断裂"：50% 占空比的虚线在拐角上盖住了 **64%** 的中轴，因为跳变
直接跳过了一个空档，两段虚线连成了一段。

修法是 `Nearest.along`——把两条臂的世界坐标按**角度**线性混合，在各自的切点上正好
接上。相邻步长 14 → 1.85（直路本身是 1.0），占空比 64% → 38–40%。

它刻意**不碰 `axis`**：圆弧波浪线的 `ARC_CEILING` 是照着旧行为量的，所以那条路径仍
带着 14px 的跳变。它也**不是弧长**：拐角的真实路径比它替掉的两条直边短（bend=11 时
26.3 对 31），而两条边界又都必须报自己的世界坐标，这个差消不掉——它变成虚线在弯道
上被拉长。

### ⚠ 路口不收线，这和参数化直觉相反

早先的实现在路口前收住轴向花纹（收束半径取被横穿那条路的半宽），理由是真实道路划线
就停在那里。**量了参考图之后这条被推翻了**：四岔那张 13 个中轴像素里有 5 个就落在
离中心 7.25 以内，三岔的是 5–7 个。土路的线是直接穿过去的。

但**路口处不能拿骨架去卡阈值**——骨架用半径 `bend`=11 的圆弧接两条臂，而路只有
14.5px 宽，细线一卡就把那些圆弧描成四条长对角线，画出来是个**星形不是十字**。所以
路口（3 臂以上）改从**臂**上取坐标：从格心出发的直射线，一个方向一条，取最近的那条。
两臂的拐角不算路口，仍旧跟着路自己的弯——一条线转弯不是几条线相遇，而且拐角那张的
轮廓根本盖不住直角 L 需要的那个肘部。

### 一条臂什么时候会被 `bend` 往里缩

只有**没有对向臂、但有垂直臂**的臂才缩。

这条规则不是风格选择，是修一个具体的 bug：无条件缩所有臂时，T 型路口中心会漏一个洞
（`bend=8` 时中心离最近的骨架 3.31px，任何小于它的半宽都会把路口渲染成两条互不相连
的路）。保留直通对不缩，从源头解决，顺带让断头路的圆头留在格子中心而不是随滑杆往里
退。`pathField.test.ts` 里的连通性测试就是为它写的。

## 接缝

这是整个方案能成立的关键，而且是可证明的，不是"看着还行"：

- **开放边**（路穿过去的那条边）：两块图块各自算出的场值**逐像素完全相同**
  （全部 16×16 组合、所有参数下实测误差 `0.00e+0` px）。因为靠近格边时最近的骨架点
  一定落在那条垂直于格边的直臂上，两边算的是同一个表达式。
- **封闭边**：两边的场值确实不同（`bend=8` 时最大差 12.65px），但都在透明区里，
  所以看不见。骨架永远不出中心十字。

三个阶段各自都不许破坏它，各自都有逐 mask 的断言：

- **圆弧波浪线只能往内咬。** 往外鼓会点亮离骨架 7.25–10.25 的像素，而在那个距离上，
  拐角格最近的元素可能是**另一条臂**，`s` 就来自另一条世界轴，两块必须一致的边界
  剖面就此分家。12 组 arcWave 设置全部这样挂掉。
- **边界噪点可以两边都抖**，因为它是**纯粹的全局位置函数**——不读 `s`，也就无从关心
  `s` 来自哪条轴。实测 576 次边界比对零分裂。`wave` / `scallop` 这两个读 `s` 的样式
  因此被排除在外，这不是整洁问题而是承重的。
- **路面只换颜色**，一个像素都不增不减，所以边界那整套证明原封不动。

### 硬约束

```
边界到中心的距离  ≤  tileSize/2 - 0.5   （32px 下是 15.5）
```

而且是紧的：`MAX_EDGE_DISTANCE === BORDER_CLEARANCE`，测试断言两个方向都没有余量。
孤立格那个圆点原本会先撞上（半径是 `距离 × dotScale`），现在 `dotScaleFor` 把倍率
跟着收，所以卡住的是路自己。⚠ 它同时要吃掉噪点的幅度——圆点半径是
`scale × (距离 + 噪点)`，从余量里减是想当然的错答案，会要 15.8 去撞 15.5。

## 运行

```bash
npm install
npm run dev
```

或从仓库根目录一起跑：

```bash
node start-local.mjs
```

然后打开 `http://localhost:3000/autotile_path/`。

```bash
npm run build   # tsc + vite build
npm test        # vitest
npm run lint    # eslint
```

`tsx` 是 devDependency 但仓库里没有脚本引用它，这是**故意留的**：这个项目的做法是
凡事先量再改，一次性的测量脚本用它跑（`node node_modules/tsx/dist/cli.mjs 某个.ts`），
脚本本身不进仓库。README 和代码注释里所有"实测"的数字都是这么来的。

## 导出

**下载 PNG + JSON** 产出一个 zip：

```
tileset_path2edge_32px.png    128×128，4×4
tileset_path2edge_32px.json   布局 + bits→槽位 LUT + 完整配方
```

4×4 的槽位顺序直接抄自引擎的 `TWO_EDGE_MATRIX`（`src/core/palette.cpp`，
`reroll/src/pack/autotile.ts` 里有镜像），所以导出的图能不加转换地进
`TERRAIN_2_EDGE` palette。JSON 里 `scheme` 字段跟着当前读法写
`"two-edge-network"` 或 `"two-edge-area"`：同样 16 个 mask 两种含义，
猜错的导入方会得到一张看起来合理、连起来却不对的图集。

## 边界

- 没有世界空间材质。和 `autotile_mixer` 的 texture 重合是故意的。
- 路沿以外是硬透明边，没有半透明过渡——像素画本来就不做 alpha 混合，而且图块也无从
  知道要往什么颜色过渡。
- tile 尺寸固定 32px。
- 界面只有中文。
