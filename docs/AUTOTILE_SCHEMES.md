# Autotile 方案：2-corner / 2-edge / blob47

> 日期：2026-08-03
> 性质：长期技术参考。推导 + 实现约束，不是决策记录。
> 相关：[`TILEMAP_FOCUS_REVIEW.md`](TILEMAP_FOCUS_REVIEW.md)（方向评审）

---

## 0. 摘要

- 2-corner 和 2-edge **不能互相转换**——两个方向都只能覆盖 16 种配置里的 10 种，
  各自都有对方表达不了的情形（§2）。
- 但降到 **quadrant（半图块）粒度**，两者恰好互补：blob 需要的 20 个基元里，
  2-edge 供 16 个，2-corner 供剩下 4 个内凹角（§4）。
- **两张纯地形纹理可以直接生成 blob47**，不需要先有 corner 或 edge 图集。
  纹理只提供材质，形状全在 mask 里（§5）。
- 推荐做法：**到 B 格并集的距离场（union-of-squares SDF）**。一个公式覆盖全部
  47 种，而且 256→47 的去重规则是从几何里掉出来的，不用手写（§5.2）。

---

## 1. 三种方案的语义差别

| | 2-corner | 2-edge | blob47 |
| --- | --- | --- | --- |
| tile 由什么决定 | 4 个**角顶点**的地形归属 | 4 个**正交邻居**是否同地形 | **8 个邻居**（4 边 + 4 对角） |
| 张数 | 16 | 16 | 47 |
| 边界位置 | 穿过图块内部（对偶网格） | 落在格子边界上 | 落在格子边界上 |
| 画什么 | 顶点 | 格子 | 格子 |
| 适合 | 区域（地形） | 区域（廉价版，忽略对角）或网络（路/河/墙） | 区域（完整，含内凹角） |

引擎侧定义见 `reroll/src/pack/autotile.ts` 的 `bitsTwoCorner` / `bitsTwoEdge`
（移植自 `src/core/palette.cpp`）。

> **要点**：2-corner 描述的是**区域**，2-edge 在路网语义下描述的是**网络**。
> 两者不是同一件事的两种方言。

---

## 2. corner ↔ edge 不可互转（两个方向都是 10/16）

两者之间唯一自然的桥是「相邻取与」。

### 2.1 corner → edge

```
N = TL ∧ TR    E = TR ∧ BR    S = BR ∧ BL    W = BL ∧ TL
```

枚举 16 个 corner mask，可达的 edge mask 只有 **10** 种：空、4 个单边、
4 个 L 形拐角、全满。

**够不到的 6 种**：`{N,S}`、`{E,W}`（直通）+ 4 个 T 形三通。
要 `{N,S}` 得同时满足 TL∧TR 和 BL∧BR，那四角全亮，E 和 W 也跟着亮——矛盾。

> 这 6 种恰好是路网最核心的图块。所以**用 corner 素材做路网是错的源材料**。

### 2.2 edge → corner

顶点 TL 由 C / N / W / NW 四格共享，而 2-edge 丢掉了对角信息，只能约定
`NW = N ∧ W`，于是（C 恒为 A）：

```
TL = N ∧ W    TR = N ∧ E    BR = S ∧ E    BL = S ∧ W
```

同样只到 **10** 种 corner mask，够不到对角对（鞍点）和 4 个三元组。

更糟的是 **7 个 edge mask 全部塌缩到「四角都不是 A」**：`{}`、4 个单边、
`{N,S}`、`{E,W}`——这些格子本身明明是地形 A，却会渲染成纯背景。

这不是推导意外，是 corner/dual-grid autotiling 的经典硬限制：

> **corner 方案画不出 1 格宽的东西。** 因为 1 格宽的地形带上，不存在任何一个
> 四邻全为 A 的顶点。

### 2.3 对称性

两个方向都是 10/16，都缺「2 个对角对 + 4 个三元组」——因为本质上是同一个布尔
结构（相邻取与）作用在互为对偶的网格上。

---

## 3. 几何根因：差半个图块

corner Wang 等价于在**对偶网格**上跑 marching squares，对偶网格相对格子网格
偏移半个图块。

- corner 图集的 A/B 边界**穿过图块内部**，从边中点进出
- edge / blob 图集的边界**落在格子边界上**，格子内部实心

所以即便是「一条竖直直边」这种双方都有的情形，两套素材里边界的**位置也差
半个 tile**。

这个偏移在 §4 反而是好事。

---

## 4. quadrant 粒度：两者恰好互补

§2 的不可能性是 **tile 级重映射**的结论。降到 quadrant 粒度，账完全不同。

blob 的标准构造：拆成 4 个象限，每个象限只依赖 **3 bit**——相邻的 2 条边 +
夹在中间的对角。对角只在两条边都连通时才有意义，故每个位置 **5 种状态**：

| # | 两条边 | 对角 | 象限外观 |
|---|---|---|---|
| 1 | 都连 | 连 | 实心内部 |
| 2 | 都连 | **断** | **内凹角**（缺口） |
| 3 | 一连一断 | — | 直边 |
| 4 | 一断一连 | — | 直边（另一侧） |
| 5 | 都断 | — | 外凸角 |

4 位置 × 5 状态 = **20 个 quadrant 基元**，拼出全部 47 张。

- **2-edge 集**知道两条边、不知道对角 → 覆盖状态 1/3/4/5 = **16 个基元**
- **缺的正好是 4 个内凹角**（状态 2）
- **2-corner 集**的「三角 A、一角 B」那张，B 象限就是一块 B 从格角侵入 A 的场，
  边界从一条边中点画到相邻边中点——**和 blob 的内凹角是同一张图**。§3 的半图块
  偏移在这里对齐了：两者都锚定在角点上。

**16 + 4 = 20，不多不少。**

⚠️ 严格成立的对象是 **mask**，不是烘焙好的像素。理想 corner Wang 里某象限只依赖
那一个角的标签，前提是相邻象限之间的过渡**合成时算出来**而非画死。
`autotile_mixer` 满足（A over B 的 alpha 合成）；手绘不透明图集只能近似。

## 5. 两张纹理 → blob47

### 5.1 为什么 2 张就够

`autotile_mixer/src/utils/tiles.ts` 的 `blendTilePixels` 结构是：

```
算 weight → smoothness 软化 → easing → noise 扰动 → A over B alpha 合成
```

纹理只在最后一步进入，**只负责材质**；形状全部来自 weight。所以换 mask 函数就能
换方案，输入纹理张数不变。

### 5.2 推荐：到 B 格并集的距离场

不要写 47 个 case。把 8 bit 邻域摊成 3×3 二值网格（中心恒为 A），对中心格内的
像素 p（格子坐标 [0,1]²，y 向下）：

```
boxDist(p, box) = hypot( max(x0-px, 0, px-x1), max(y0-py, 0, py-y1) )
dB     = min over 所有 B 邻居 cell 的 boxDist(p, cell)
weight = clamp(dB / r)
```

邻居 (dx,dy) 的方格是 `[dx, dx+1] × [dy, dy+1]`。自动得到：

- 正交邻居 N 是 B → `dB = py` → **直边**
- 对角 NE 是 B（N、E 都是 A）→ `dB = hypot(1-px, py)` → **半径 r 的圆弧内凹角**
- N、E 都是 B → min 取到两条直边 → **外凸角**
- 全部邻居是 A → `dB = ∞` → weight ≡ 1 → **实心内部**

算出的 weight 直接接进现有的 smoothness / easing / noise / 合成管线，尾部一行不改。

### 5.3 256 → 47 的去重是自动的

**命题**：只要某条邻边是 B，它那侧的对角就永远影响不了 `dB`。

**证明**：设 N 是 B，取 NE 角附近像素 (px, py)。到 N 格距离 = `py`；
到 NE 格距离 = `hypot(1-px, py) ≥ py`。故 min 恒由 N 主导。E 为 B 时同理。∎

所以**对角只在两条邻边都为 A 时才起作用**——这正是 blob47 从 256 收敛到 47 的
规则。它是从几何里掉出来的，不需要编码进去。

> 这条性质是天然的 golden test：枚举 256 种邻域、算 mask、哈希去重，
> 断言恰好 47 个不同结果。

## 6. 实现约束（会踩的坑）

### 6.1 ⚠️ 现有 noise 方案在 blob 下会失效

`tiles.ts` 当前的做法：

```js
const edgeFade = Math.sin(tx * Math.PI) * Math.sin(ty * Math.PI); // 0 at tile edges
```

corner 模式下这是对的——边界穿过图块**中心**，噪声在中心最强、图块边缘归零，
既有抖动又无缝。

但 **blob47 的边界恰恰在格子边缘上**，`edgeFade` 会在那里把噪声精确清零，
所有过渡退化成光溜溜的几何直线/圆弧，和 corner 集的有机感对不上。

**修法不是调参数，是换机制**：噪声改成**以 tileSize 为周期的可平铺噪声**，
靠周期性（而非淡出）保证接缝连续——相邻放置的两张图块显示同一段周期图案，
边界处自然连续。

### 6.2 过渡带半径有上限

`r` 必须 < 1 个 tile，否则距离场会依赖 5×5 邻域，而 blob47 只编码 3×3——
超了会出现「同一张 tile 在不同上下文需要不同外观」的矛盾，表现为接缝。
实用上 `r ≤ 0.5 tile`。

### 6.3 外凸角默认是直角

并集 SDF 的性质：**凹角自动圆滑**（半径 r 的圆弧），**凸角保持 90° 尖角**。

要圆外角，把 `min` 换成多项式 smooth-min：

```
smin(a, b, k) = min(a,b) - h²·k/4,   h = max(k - |a-b|, 0) / k
```

`k = 0` 退化为普通 min。这个 smin 版本会一并涵盖现有的 `arc` maskStyle；
`pixel` 模式照常可用（先量化 tx/ty 再算 SDF）。

### 6.4 纹理需在 tileSize 上无缝

`getSourcePixel` 用 modulo 包裹纹理，且所有图块都用 tile-local 的 `(x, y)` 采样，
即**每张图块采的是同一个纹理窗口**。因此相邻放置的图块要连续，源纹理必须在
tileSize 上可平铺。（这条对现有 corner 模式同样成立，不是 blob 引入的。）

## 7. 现状注记：当前的「blob 13+1」不是 blob

`tiles.ts` 的 `BLOB_CORNERS` 是 14 组**4 角配置**，喂进和 Wang 完全相同的
`calculateWangBaseWeight`；`App.tsx` 的 playground 注释也写着
`// Both modes use corner-based (vertex) rendering`，索引走
`(nw<<3)|(sw<<2)|(se<<1)|ne` 再查 `WANG_TO_BLOB`。

**它是 corner-Wang 换了名字和布局**——同一个对偶网格模型，挑了 14 种配置重排，
不是 cell-based 的 blob。

因此 blob47 是**新增第三个模型**，不是扩充现有 blob 模式。要动四处：

1. mask 函数（4 bit → 8 bit）
2. 索引计算（4 顶点 → 8 邻居）
3. 布局表（4×4 / 5×3 → **6×8**，47 张 + 1 背景 = 48 格）
4. playground painting（画顶点 → 画格子）

---

## 8. 位序约定

沿用引擎风格（`src/util/misc.cpp` 的 Dir4/Corner4）：

```
边：  N = 1,  E = 2,   S = 4,   W = 8
角：  NE = 16, SE = 32, SW = 64, NW = 128
```

规范化（canonicalize）：角 bit 只在其两条邻边都置位时保留，否则清零。
256 个原始 mask 经规范化后恰好剩 47 个。
